# Quickstart: Terminal.Gui XAML Framework

## Complete XAML-to-UI Workflow

### Scenario 1: Simple Terminal.Gui Application with XAML

**Goal**: Create a basic Terminal.Gui application using XAML for UI definition

**Prerequisites**:
- .NET 8 SDK installed
- Terminal.Gui v2+ package reference
- Terminal.Gui.Xaml framework package

**Steps**:

1. **Create Project Structure**
   ```bash
   dotnet new console -n XamlTerminalApp
   cd XamlTerminalApp
   dotnet add package Terminal.Gui --version 2.0.0
   dotnet add package Terminal.Gui.Xaml --version 1.0.0
   ```

2. **Create XAML File** (`MainWindow.xaml`)
   ```xml
   <Window xmlns="http://schemas.terminal-gui.org/xaml"
           Title="XAML Terminal App"
           Width="80" Height="25">
       <StackView Orientation="Vertical">
           <Label Text="Welcome to Terminal.Gui XAML!" />
           <Button x:Name="ClickMe" Text="Click Me" Clicked="OnClickMeClicked" />
           <TextField x:Name="UserInput" Text="{Binding UserText}" />
           <Label Text="{Binding DisplayText}" />
       </StackView>
   </Window>
   ```

3. **Create Code-Behind** (`MainWindow.xaml.cs`)
   ```csharp
   using Terminal.Gui;
   using Terminal.Gui.Xaml;
   
   namespace XamlTerminalApp;
   
   public partial class MainWindow : Window
   {
       public string UserText { get; set; } = "";
       public string DisplayText { get; set; } = "Enter text above";
       
       public MainWindow()
       {
           InitializeComponent(); // Generated by XAML framework
           DataContext = this;
       }
       
       private void OnClickMeClicked(object? sender, EventArgs e)
       {
           DisplayText = $"You entered: {UserText}";
           // Property change notifications handled by framework
       }
   }
   ```

4. **Create Application Entry Point** (`Program.cs`)
   ```csharp
   using Terminal.Gui;
   using XamlTerminalApp;
   
   Application.Init();
   
   var mainWindow = new MainWindow();
   Application.Run(mainWindow);
   
   Application.Shutdown();
   ```

5. **Build and Run**
   ```bash
   dotnet build
   dotnet run
   ```

**Expected Results**:
- ✅ XAML file is parsed during build
- ✅ C# code is generated for InitializeComponent()
- ✅ Data binding works between XAML and code-behind
- ✅ Event handlers are properly connected
- ✅ Application runs cross-platform (Windows/Linux/macOS)

**Performance Validation**:
- ✅ XAML parsing completes <100ms
- ✅ Application startup <50ms
- ✅ UI interactions maintain >30 FPS
- ✅ Memory usage stays <50MB

### Scenario 2: MVVM Pattern Implementation

**Goal**: Demonstrate MVVM pattern support with data binding

**Steps**:

1. **Create ViewModel** (`MainViewModel.cs`)
   ```csharp
   using System.ComponentModel;
   using System.Runtime.CompilerServices;
   
   public class MainViewModel : INotifyPropertyChanged
   {
       private string _message = "Hello MVVM!";
       private string _inputText = "";
       
       public string Message
       {
           get => _message;
           set => SetProperty(ref _message, value);
       }
       
       public string InputText
       {
           get => _inputText;
           set => SetProperty(ref _inputText, value);
       }
       
       public event PropertyChangedEventHandler? PropertyChanged;
       
       protected virtual void OnPropertyChanged([CallerMemberName] string? propertyName = null)
       {
           PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(propertyName));
       }
       
       protected bool SetProperty<T>(ref T field, T value, [CallerMemberName] string? propertyName = null)
       {
           if (EqualityComparer<T>.Default.Equals(field, value)) return false;
           field = value;
           OnPropertyChanged(propertyName);
           return true;
       }
   }
   ```

2. **Update XAML** (`MainWindow.xaml`)
   ```xml
   <Window xmlns="http://schemas.terminal-gui.org/xaml"
           Title="MVVM Terminal App">
       <StackView Orientation="Vertical">
           <Label Text="{Binding Message}" />
           <TextField Text="{Binding InputText, Mode=TwoWay}" />
           <Button Text="Update Message" 
                   Command="{Binding UpdateMessageCommand}" />
       </StackView>
   </Window>
   ```

3. **Update Code-Behind** (`MainWindow.xaml.cs`)
   ```csharp
   public partial class MainWindow : Window
   {
       public MainWindow()
       {
           InitializeComponent();
           DataContext = new MainViewModel();
       }
   }
   ```

**Expected Results**:
- ✅ Two-way data binding functions correctly
- ✅ Property change notifications update UI automatically
- ✅ MVVM pattern is properly supported
- ✅ Command binding works (if implemented)

### Scenario 3: Custom Control Integration

**Goal**: Integrate custom Terminal.Gui controls with XAML

**Steps**:

1. **Create Custom Control** (`CustomButton.cs`)
   ```csharp
   using Terminal.Gui;
   
   public class CustomButton : Button
   {
       public string CustomProperty { get; set; } = "";
       
       public CustomButton() : base()
       {
           // Custom initialization
       }
   }
   ```

2. **Register Control** (in startup code)
   ```csharp
   XamlControlRegistry.RegisterControl<CustomButton>("CustomButton");
   ```

3. **Use in XAML**
   ```xml
   <Window xmlns="http://schemas.terminal-gui.org/xaml"
           xmlns:custom="clr-namespace:XamlTerminalApp">
       <StackView>
           <custom:CustomButton Text="Custom Button"
                                CustomProperty="Custom Value" />
       </StackView>
   </Window>
   ```

**Expected Results**:
- ✅ Custom controls are recognized in XAML
- ✅ Custom properties are properly set
- ✅ Design-time IntelliSense includes custom controls
- ✅ Generated code properly instantiates custom controls

### Scenario 4: Error Handling and Validation

**Goal**: Validate framework error handling and reporting

**Test Cases**:

1. **Invalid XAML Syntax**
   ```xml
   <Window xmlns="http://schemas.terminal-gui.org/xaml">
       <Label Text="Missing closing tag"
   ```
   **Expected**: Clear build error with line number

2. **Invalid Property Reference**
   ```xml
   <Button NonExistentProperty="value" />
   ```
   **Expected**: Build warning with suggestion

3. **Invalid Binding Path**
   ```xml
   <Label Text="{Binding NonExistent.Property}" />
   ```
   **Expected**: Runtime binding error with graceful fallback

4. **Missing Event Handler**
   ```xml
   <Button Clicked="NonExistentHandler" />
   ```
   **Expected**: Build error with method signature suggestion

**Expected Results**:
- ✅ All errors provide clear, actionable messages
- ✅ Line numbers and context are provided
- ✅ Suggestions for fixes are included
- ✅ Application doesn't crash on binding errors
