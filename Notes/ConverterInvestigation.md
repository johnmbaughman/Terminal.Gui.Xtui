# Converter / Resources Generator Investigation

Summary
- Goal: generator emits InitializeComponent code that wires Bindings and Converters for Xtui-style XAML without adding a runtime reference to `Terminal.Gui.Xtui`.
- Constraint: `View` and `UserControl` live in another assembly. The generated code must not depend on `Terminal.Gui.Xtui`.
- Approach: generator emits a per-file helper (inserted into the generated `.g.cs`) that provides per-instance `Resources` and attached-like setters via `ConditionalWeakTable<View,Holder>`. The generated code then uses those helpers to register resources and assign converters.

IValueConverter sample

Below is a minimal `IValueConverter` contract (WinRT-style) and a tiny example `BoolToTextConverter` implementation that demonstrates the kinds of converter shapes the generator should recognize and emit references to (cached field, `x:Static` access, or `new` instances).

```csharp
using System;

public interface IValueConverter
{
    // Convert a source value to a target value.
    object? Convert(object? value, Type targetType, object? parameter, string? language);

    // Convert a target value back to a source value (optional; may throw or return null if not supported).
    object? ConvertBack(object? value, Type targetType, object? parameter, string? language);
}

// Example converter the generator may emit references to.
public sealed class BoolToTextConverter : IValueConverter
{
    // Optional singleton instance pattern (generator can emit `BoolToTextConverter.Instance` for x:Static cases)
    public static readonly BoolToTextConverter Instance = new BoolToTextConverter();

    public object? Convert(object? value, Type targetType, object? parameter, string? language)
    {
        if (value is bool b) return b ? "True" : "False";
        return null;
    }

    public object? ConvertBack(object? value, Type targetType, object? parameter, string? language)
    {
        if (value is string s && bool.TryParse(s, out var b)) return b;
        return null;
    }
}
```

Example input XAML
```xml
<UserControl x:Class="MyApp.Views.MainView"
             xmlns="http://schemas.microsoft.com/winfx/2006/xaml"
             xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
             xmlns:local="clr-namespace:MyApp.Converters">
  <UserControl.Resources>
    <local:BoolToTextConverter x:Key="BoolToText" />
  </UserControl.Resources>

  <StackPanel>
    <TextBlock x:Name="tb1" Text="{Binding IsActive, Converter={StaticResource BoolToText}}" />
    <TextBlock x:Name="tb2" Text="{Binding IsEnabled, Converter={x:Static local:BoolToTextConverter.Instance}}" />
    <TextBlock x:Name="tb3" Text="{Binding IsVisible, Converter={local:BoolToTextConverter}}" />
  </StackPanel>
</UserControl>
```

Generated pattern (what the source-generator should emit)

- The generator emits a `.Xtui.g.cs` partial class for the `x:Class` type.
- It includes a small private helper type (placed inside the generated class or nested private static class) that implements per-instance `Resources` and attached-like setters via `ConditionalWeakTable<View,Holder>`.
- All resource registration and lookups use that helper. This keeps generated code self-contained and avoids any dependency on `Terminal.Gui.Xtui`.

Example generated `.Xtui.g.cs` (fully self-contained helper)

```csharp
// <auto-generated />
using System;
using System.Collections.Generic;
using System.Runtime.CompilerServices;
using Terminal.Gui.ViewBase; // runtime assembly types (View, Binding, TextBlock, etc.)

namespace MyApp.Views
{
    partial class MainView
    {
        // Per-generated-file helper: provides per-instance Resources and attached-like setters.
        private static class __XtuiGeneratedHelpers
        {
            private class Holder
            {
                public IDictionary<string, object>? Resources;
                public string? XtuiTag;
            }

            private static readonly ConditionalWeakTable<View, Holder> s_table = new();

            public static IDictionary<string, object> GetResources(View v) =>
                s_table.GetOrCreateValue(v).Resources ??= new Dictionary<string, object>();

            public static void SetResource(View v, string key, object value) =>
                GetResources(v)[key] = value;

            public static bool TryGetResource(View v, string key, out object? value)
            {
                var h = s_table.GetOrCreateValue(v);
                if (h.Resources != null && h.Resources.TryGetValue(key, out value)) return true;
                value = null;
                return false;
            }

            public static void SetXtuiTag(View v, string? tag) => s_table.GetOrCreateValue(v).XtuiTag = tag;
            public static string? GetXtuiTag(View v) => s_table.GetOrCreateValue(v).XtuiTag;
        }

        // Cached compiled resource instance (emitted when generator can resolve converter type)
        private static readonly MyApp.Converters.BoolToTextConverter _res_BoolToText = new MyApp.Converters.BoolToTextConverter();

        public void InitializeComponent()
        {
            // register compiled resource into per-instance storage for this UserControl
            __XtuiGeneratedHelpers.SetResource(this, "BoolToText", _res_BoolToText);

            // Element construction (simplified for example)
            var tb1 = new TextBlock();
            var tb2 = new TextBlock();
            var tb3 = new TextBlock();

            // Binding #1: converter from compiled UserControl.Resources
            var binding1 = new Binding("IsActive");
            if (__XtuiGeneratedHelpers.TryGetResource(this, "BoolToText", out var __r1))
                binding1.Converter = (IValueConverter)__r1;
            else
                binding1.Converter = null; // fallback
            tb1.SetBinding(TextBlock.TextProperty, binding1);

            // Binding #2: x:Static resolved at generator time
            var binding2 = new Binding("IsEnabled");
            binding2.Converter = MyApp.Converters.BoolToTextConverter.Instance; // emitted as static access
            tb2.SetBinding(TextBlock.TextProperty, binding2);

            // Binding #3: inline/new instance converter
            var binding3 = new Binding("IsVisible");
            binding3.Converter = new MyApp.Converters.BoolToTextConverter();
            tb3.SetBinding(TextBlock.TextProperty, binding3);

            // Example: set attached-like property via helper (cannot add real property to external View)
            var btn = new Button();
            __XtuiGeneratedHelpers.SetXtuiTag(btn, "main-btn");
        }
    }
}
```

Generator emission sketch (pseudo-code)

- Input: parsed XAML model with discovered bindings, resources, x:Class, and resolved type/member names from semantic model.
- Output: string source for `.Xtui.g.cs`.

Key emission rules:
1. Emit using directives including `Terminal.Gui.ViewBase` (or fully-qualify runtime types).
2. Emit a private helper `__XtuiGeneratedHelpers` inside the generated partial class. This guarantees there is no runtime dependency on `Terminal.Gui.Xtui`.
3. For each resource declared in the same XAML that the generator can resolve to a concrete type implementing `IValueConverter`, emit a private static readonly cached instance field and `SetResource(this, key, instance)` in `InitializeComponent`.
4. For `{StaticResource Key}` bindings, prefer `TryGetResource(this, Key, out var r)` and use `(IValueConverter)r`.
5. For `{x:Static Type.Member}` bindings, if the generator resolves the symbol, emit fully-qualified `Type.Member` access directly as the converter expression.
6. For inline converter elements, emit `new FullyQualifiedConverterType()` (or emit a shared cached field if you prefer reuse).
7. For attached-like properties (anything you cannot add to `View`), emit helper calls like `__XtuiGeneratedHelpers.SetXtuiTag(view, value)`.

Notes and trade-offs
- Placing the helper in each generated file keeps the generated code self-contained and avoids adding a helper assembly reference. You can deduplicate the helper by emitting it once per compilation unit (generator-level optimization), but per-file is simplest.
- `ConditionalWeakTable` ensures stored data doesn't keep `View` instances alive.
- This approach models `UserControl.Resources` behavior for resources declared in the same XAML. It cannot automatically resolve external merged dictionaries at compile time; for those, the generated code should fallback to `TryGetResource` and document runtime merging expectations.
- Because the generated file is compiled into the user's assembly, it has access to the local types and doesn't need to reference the generator project.
